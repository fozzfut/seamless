# repro/python — воспроизведение измерений о шве

Девять скриптов. Каждый запускается сам по себе, печатает измеренные числа и выходит.
Ничего интерактивного, ни одного окна. Восемь из девяти строят всю геометрию с нуля
и не зависят ни от каких файлов; девятый (`07_user_part_fillet.py`) работает с деталью
владельца и **копирует** её, оригинал не открывает никогда.

Полное изложение результатов — `docs/MEASUREMENTS.md`.

Каталог `repro/cpp/` — другая линия работы (воспроизведение на чистом OCCT), у неё свой
README. Скрипты `same_solid_proof.py`, `seam_pcurve.py`, `seam_sweep.py` в этом же
каталоге тоже относятся к ней, а не к этому набору.

---

## Как запускать

```
cd repro/python
timeout -k 5 540 "C:/Program Files/FreeCAD 1.1/bin/FreeCADCmd.exe" 01_seam_anatomy.py 2>&1 1>/dev/null
```

Три вещи, которые нужно знать заранее.

**1. Измерения печатаются в stderr, а не в stdout.** Это сделано нарочно. FreeCAD пишет
свой баннер и индикатор `Recompute...  (37 %)` с возвратами каретки в stdout и не
сбрасывает буфер до выхода процесса; если потоки смешать, строки с числами затираются
процентами. Поэтому:

```
... 2>&1 1>/dev/null      # только измерения, ничего лишнего
... 2>out.txt 1>/dev/null # то же самое в файл
...                       # без перенаправления: сначала измерения, потом мусор FreeCAD
```

Ошибки самого ядра (`Tool shape is not valid for boolean operation`,
`Helix: Error: Adding the helix failed`) тоже идут в stderr и потому попадают в поток
измерений. Это не сбой скрипта — это ядро говорит вслух, и в разделах 9.1 и 9.2
документа измерений такие строки как раз и есть предмет измерения.

**2. `timeout` обязателен.** Скругление рядом со швом может не вернуться вовсе.
Измерено: `07_user_part_fillet.py` при `r = 0.5` на реальной детали был убит по дедлайну
542 с, так и не выйдя из `doc.recompute()`. Убитый прогон — это результат, а не авария;
последняя напечатанная строка показывает, докуда он дошёл.

**3. Только headless.** `FreeCADCmd.exe`, не `FreeCAD.exe`. Ни один скрипт не
открывает окно и не требует GUI.

Проверить всё разом (кроме зависающих радиусов):

```
cd repro/python
for s in 01_seam_anatomy 02_two_pcurves 03_minimal_pair 04_isvalid_vs_bop \
         05_removing_the_seam 06_python_reach 08_thread_turns 09_helix_profile; do
  timeout -k 5 540 "C:/Program Files/FreeCAD 1.1/bin/FreeCADCmd.exe" $s.py 2>/tmp/$s.txt 1>/dev/null
  echo "$s exit=$?"
done
```

## Что доказывает каждый скрипт и сколько занимает

Время измерено на машине владельца (`FreeCAD 1.1.1`, OCCT 7.8.1, Windows 10) как
полное время процесса, включая запуск FreeCAD (около 0.25 с сам по себе). Указан
разброс по двум прогонам подряд.

| Скрипт | Что доказывает | Время | Нужен файл |
|---|---|---|---|
| `01_seam_anatomy.py` | шов — изо-линия `u = 0`; детектор «одна смежная грань»; якорь `Center + R*Rot*(1,0,0)`; при 359° шва нет | **0.23 с** | нет |
| `02_two_pcurves.py` | одно ребро — две pcurve на одной грани; обычное ребро — по одной на каждой из двух; `OrderedEdges` обходит шов дважды | **0.23 с** | нет |
| `03_minimal_pair.py` | минимальная пара (различие только в `AngleXU`), доказательство тождества тел; порог расстояния и его масштабирование с радиусом | **25.5–28.6 с** | нет |
| `04_isvalid_vs_bop.py` | `isValid() = True` при грязном `check(True)`; тор, разрезанный швом пополам | **1.7 с** | нет |
| `05_removing_the_seam.py` | шва можно не создавать: разбитый профиль + `Refine = False`; что сохраняет бесшовность, а что возвращает шов | **1.0 с** | нет |
| `06_python_reach.py` | `ShapeDivideClosed` не привязан; `Part.ShapeFix` существует; удалить шов из Python нечем | **0.25 с** | нет |
| `07_user_part_fillet.py` | реальная деталь: чистая база, шов на вершине, развёртка по радиусу, полоса зависания | **см. ниже** | **да** |
| `08_thread_turns.py` | `Part.makeThread` выдаёт 0.2690 витка из 32; остальные построители — полное число | **37.8–41.8 с** | нет |
| `09_helix_profile.py` | `AdditiveHelix` ломается при `2h == pitch` и молча съедает сердцевину выше `2h/pitch = 1.20` | **6.3–6.7 с** | нет |

Долгие места: в `03` — развёртка по 61 углу для четырёх радиусов, то есть 244
построения стенда; в `08` — приваривание 32-виткового заметания к стержню, на которое
уходит почти всё время скрипта (41.2 с из 41.8 с в одном из прогонов).

## `07_user_part_fillet.py` — единственный, которому нужен документ

Копирует `.FCStd` во временный каталог и открывает **копию**. Оригинал не открывается
ни при каком исходе, поэтому испортить его нельзя.

Один радиус за запуск — специально, потому что часть радиусов не возвращается и каждый
должен иметь свой собственный внешний дедлайн.

```
SEAMLESS_RADIUS=0.25 timeout -k 5 540 \
  "C:/Program Files/FreeCAD 1.1/bin/FreeCADCmd.exe" 07_user_part_fillet.py 2>&1 1>/dev/null
```

Переменные окружения:

| Переменная | Значение по умолчанию | Смысл |
|---|---|---|
| `SEAMLESS_PART` | деталь владельца, `.../scratchpad/ribact/part with fillet.FCStd` | путь к `.FCStd` |
| `SEAMLESS_RADIUS` | `1.0` | радиус скругления, мм |
| `SEAMLESS_EDGE` | `Edge9` | имя ребра на `Body.Tip` |
| `SEAMLESS_WORK` | `%TEMP%/seamless_repro` | куда класть копию |

Если файла нет, скрипт печатает это и выходит с кодом 2 — он не падает и ничего не ждёт.

Время по радиусам (полное время процесса):

| r, мм | код выхода | время процесса | что произошло |
|---|---|---|---|
| 0.10 | 0 | 0.811 с | вернулось за 0.033 с, `isValid = False` |
| 0.25 | 0 | 0.850 с | вернулось за 0.028 с, `isValid = True`, BOP грязный |
| 0.45 | 0 | 0.815 с | вернулось за 0.035 с, `isValid = False` |
| 0.50 | **124** | 542 с | `doc.recompute()` не вернулся, процесс убит |
| 0.55 | **124** | 541 с | `doc.recompute()` не вернулся, процесс убит |
| 0.60 | 0 | 0.784 с | вернулось за 0.020 с, объём вырос на 642.9480 мм3 |
| 0.75 | 0 | 0.770 с | вернулось за 0.021 с, объём вырос на 619.1511 мм3 |
| 1.00 | 0 | 0.946 с | вернулось за 0.039 с, объём вырос на 597.3323 мм3 |

Код выхода 124 от `timeout` означает, что `doc.recompute()` не вернулся. Это и есть
измерение полосы зависания.

Развёртка по всем радиусам сразу:

```
cd repro/python
for r in 0.10 0.25 0.45 0.50 0.55 0.60 0.75 1.00; do
  s=$(date +%s)
  SEAMLESS_RADIUS=$r timeout -k 5 540 \
    "C:/Program Files/FreeCAD 1.1/bin/FreeCADCmd.exe" 07_user_part_fillet.py \
    2>/tmp/r_$r.txt 1>/dev/null
  echo "r=$r exit=$? wall=$(( $(date +%s) - s ))s"
done
```

Полный проход этой развёртки занимает около 18.5 минут, из которых 18 приходятся на два
радиуса, которые не завершаются.

## `seamlib.py` — общие части

Не запускается сам по себе; импортируется остальными.

| Имя | Что делает |
|---|---|
| `say(fmt, *args)` | печать одной строки измерения в stderr, с немедленным сбросом |
| `head(title)`, `done(script)` | заголовок раздела и итоговая строка со временем |
| `seam_edges(shape)` | швы тела: рёбра, у которых ровно одна смежная грань |
| `bop(shape)` | `Part.Shape.check(True)` одной строкой: `clean` или `RAISED <виды ошибок>` |
| `u0_anchor(surface)` | `Center + R * Rotation * (1,0,0)` — точка, к которой прибит шов |
| `build_fixture(doc, tag, angle_xu, ...)` | стенд: коробка с наклонным цилиндрическим карманом; `angle_xu` двигает **только** шов |
| `target_edge(shape)` | то самое ребро, которое мы скругляем |
| `fillet_removed(r, L)`, `chamfer_removed(r, L)` | аналитический объём, который обязана снять операция |

Стенд намеренно повторяет форму реальной детали владельца: коробка
25 x 25.7184 x 10 мм, карман радиуса 6.647656 мм, ось наклонена на 45 градусов вокруг Y
и пересекает верхнее рёберное ребро коробки.

## Если числа не сойдутся

Всё в `docs/MEASUREMENTS.md` привязано к одной сборке:

```
FreeCAD 1.1.1 (20260414), OCCT 7.8.1, Python 3.11.14, Windows 10
```

На другой сборке OCCT числа могут быть другими — и это само по себе будет ценным
измерением. Тогда стоит записать новую строку рядом со старой, а не заменять её.
