# seamless — работа над швами в геометрическом ядре

Проект открыт 12 сентября 2026 года по решению владельца: сначала попытаться починить
подсистему OCCT, и, если это окажется невозможным, проектировать собственное ядро,
свободное от проблемы шва.

Repository language note: the code, comments and identifiers here are English; this README
and the documents under `docs/` are Russian, because they are read by the project owner.

## Задача одной строкой

В OCCT замкнутая по параметру грань (цилиндр, сфера, тор, поверхность вращения) обязана
нести ребро-шов. Рядом со швом отказывают операции, в первую очередь скругления. Нужно
убрать причину, а не симптом.

## Что уже измерено (FreeCAD 1.1.1, OCCT 7.8.1, 11–12 сентября 2026)

Полные числа — в `docs/MEASUREMENTS.md`. Коротко:

1. **Шов — это изо-линия u = 0 системы координат поверхности.** Точка шва равна
   `Center + R · (Rotation поверхности, применённый к (1,0,0))`. Для фич PartDesign эта
   система наследуется от параметризации окружности профиля (`AngleXU`), проведённой
   через размещение эскиза. Предсказанное и измеренное направление совпадают: `dot = 1.000000000`.
2. **Одно ребро — две параметрические кривые.** У шва `pcurve` при `u = 6.2832` и при
   `u = 0.0000`; обычное ребро принадлежит двум граням и несёт по одной кривой на каждой.
3. **Скругление ломается, когда конец шва оказывается в 0.4–1.0 мм от вершины
   скругляемого ребра.** Доказано минимальной парой, отличающейся только `AngleXU`
   (тела доказанно одинаковы — каждое режет другое в ноль): шов в 11.5 мм — скругление
   валидно, снято 1.3681 мм³ против аналитических 1.3672; шов на вершине — объём
   **растёт** на 356.45 мм³.
4. **`isValid()` в этой ситуации врёт:** «валидные» результаты не проходят проверку
   `Part.Shape.check(True)`. Проверять только ею.
5. **Часть радиусов подвешивает ядро:** на реальной детали r = 0.5 и r = 0.55 не
   завершились за 9.2 минуты.
6. **Шов нельзя ни убрать, ни переставить средствами FreeCAD Python.** Из `ShapeUpgrade`
   наружу выведен ровно один класс — `UnifySameDomain`; `ShapeDivideClosed`, `ShapeFix`,
   `ShapeAnalysis`, `BRepBuilderAPI` из Python недоступны. Разбиение окружности профиля на
   две дуги шов не убирает: ядро склеивает грани одной поверхности обратно.
7. **Резьбы.** «Один виток от шва до шва» — свойство ровно одной функции,
   `Part.makeThread` (запрошено 32 витка, получено 0.269; с 8 витков — отрицательный
   объём). Все остальные пути дают полное число витков. Настоящая беда другая и к шву
   отношения не имеет: `PartDesign::AdditiveHelix` ломается, когда осевой размер профиля
   ровно равен шагу (а это классический ISO-треугольник), и при профиле выше шага молча
   съедает сердцевину, оставаясь `Up-to-date`.

## Два пути

| | Починка OCCT | Своё ядро |
|---|---|---|
| Что меняем | подсистему, где отказ воспроизводится | модель топологии целиком |
| Совместимость | сохраняется, включая STEP и ABI FreeCAD | нужна прослойка обмена |
| Наследуем | булевы, скругления, импорт, сшивку, триангуляцию | ничего |
| Риск | дефект может оказаться неизбежным следствием модели | годы на то, что в OCCT уже работает |

Решение принимается по результатам разведки (`docs/DECISION.md`), а не заранее.

## Окружение этой машины

- FreeCAD 1.1.1 (сборка 20260414), OCCT 7.8.1, Qt 6.8.3, Python 3.11.
- Visual Studio 2022 Community, CMake из поставки VS
  (`Common7/IDE/CommonExtensions/Microsoft/CMake/CMake/bin/cmake.exe`).
  Ядро и примеры собраны компилятором MSVC 14.36.32532
  (`VC/Tools/MSVC/14.36.32532/bin/Hostx64/x64/cl.exe`), Windows SDK 10.0.22000.0.
- Заголовков OCCT в поставке FreeCAD нет — нужны исходники; собранные заголовки
  лежат в `build/occt-release/inc`.
- Свободно 28 ГБ (`df -h /c`), весь проект занимает 2,2 ГБ: полная отладочная сборка
  OCCT не поместится, собирать только нужные модули в Release.
- Каталог `install/` не под git и содержит **патченое** ядро — не коммитить и не
  брать за основу приложения (`docs/VERDICT.md`, раздел 2.3).
