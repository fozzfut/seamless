# 004. `Part.makeHelix`: `Shape.Length` врёт начиная примерно с 50 витков

| | |
|---|---|
| Чей | **не определено**: построение ребра FreeCAD (`Part.makeHelix`) или вычисление длины в OCCT |
| Статус | **измерено**, причина не искалась |
| Версии | FreeCAD 1.1.1, OCCT 7.8.1, Windows |
| Воспроизведение | `issues/002-freecad-makethread-turns/repro/python/08_thread_turns.py`, таблица витков |

## Симптом

Витки считаны двумя способами: по длине проволоки (`L`) и по фактически пройденной высоте (`Z`):

```
  asked   mkHelix L   mkHelix Z   edges   mkLong L    mkLong Z    edges
  32      32.0000     32.0000     1       32.0000     32.0000     32
  50      28.9240     50.0000     1       50.0000     50.0000     50
  100     33.0924     100.0000    1       100.0000    100.0000    100
```

Геометрия верна: высоту `makeHelix` проходит полностью при любом числе витков. Неверна только
длина единственного аналитического ребра — при 100 витках она соответствует 33.09 витка.
`makeLongHelix`, который строит одно B-сплайновое ребро на виток, считает длину верно везде.

## Чем опасно

Любой код, который берёт число витков или шаг из `Shape.Length`, получит неверный ответ без
единого предупреждения.

## Что не сделано

Не выяснено, где теряется точность: в интегрировании длины кривой на поверхности или в самом
ребре. Порог «примерно 50» — между измеренными точками 32 (верно) и 50 (неверно).
