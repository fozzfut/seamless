Дата прогона: 12 сентября 2026. Ядро: OCCT 7.8.1, тег `V7_8_1`, коммит
`bd2a789f15235755ce4d1a3b07379a2e062fdc2e`.
Патч: `patches/0001-chfi3d-recale-unconditional.patch` (снимает `if (onsame)`
перед `ChFi3d_Recale` в `ChFi3d_Builder_C1.cxx:807`).

## 0. Ответ

**Да, ломает. Патч в текущем виде НЕ пригоден к поставке.**

Собственный набор OCCT `tests/blend` прогнан на стоковом и на патченом ядре.
Из 181 случая, которые реально исполняются на этой машине, **2 случая

| случай | ожидаемая площадь | сток | патч |
|---|---|---|---|
| `blend simple H4` | 426548 | 426531, `This shape seems to be valid` | 426419, `BRepCheck_UnorientableShape` + `BRepCheck_NotClosed` |

не в пользу патча. Аргумент безопасности из раздела 2 `DECISION.md`

## 1. Что пришлось собрать, чтобы это измерить

Задача требовала `BUILD_MODULE_Draw=ON`, чтобы появился `DRAWEXE` — без него
собственный набор OCCT запустить нечем. На этой машине не было ни одной из
двух обязательных зависимостей Draw.

### 1.1. Tcl — не было заголовков, но нашлась точная версия

`DRAWEXE` линкуется с Tcl. Заголовков и импортной библиотеки в системе нет:

```
$ find "C:/Program Files/FreeCAD 1.1" -iname "tcl.h"      # пусто
$ ls /mingw64/include/tcl.h                                # No such file
$ which pacman                                             # нет (это mingw из Git for Windows)
```

Но FreeCAD поставляет **рантайм** Tcl и его скриптовую библиотеку:

```
FileVersion : 8.6.13          (C:/Program Files/FreeCAD 1.1/bin/tcl86t.dll)
C:/Program Files/FreeCAD 1.1/lib/tcl8.6/init.tcl
```

Версия — ровно 8.6.13. Исходники того же тега скачаны с upstream
(`github.com/tcltk/tcl`, тег `core-8-6-13`), из них взяты **только заголовки**;
проверено, что это та же версия:

```
$ grep TCL_PATCH_LEVEL tcl-core-8-6-13/generic/tcl.h
#define TCL_PATCH_LEVEL     "8.6.13"
```

Импортная библиотека сделана из самой DLL, без сборки Tcl:

```
$ dumpbin -exports tcl86t.dll > exports.txt      # 879 символов
$ lib -def:tcl86t.def -machine:x64 -out:tcl86t.lib
```

`USE_TK=OFF` — Tk не нужен, `DRAWEXE -b` работает без него.

**Установка FreeCAD не изменялась**: `tcl86t.dll` и скриптовая библиотека
только читались; копия DLL положена в каталог сборки OCCT.

### 1.2. FreeType — собран из исходников

`TKDraw` тянет `TKService`, а тот требует `CSF_FREETYPE`. Заголовков в системе
тоже нет. FreeType 2.13.2 собран статически своим CMake (zlib/png/bzip2/harfbuzz

Единственная переменная — содержимое `TKFillet.dll`. Всё остальное (DRAWEXE,

`ChFi3d_Builder.cxx` и `ChFi3d_Builder_C1.cxx` подменялись на эталон из

### Две поправки к окружению, одинаковые для обоих ядер

1. **`checkview` заменён на no-op.** Настоящий `checkview` открывает вид Draw и
   зовёт `xwd`, чтобы положить PNG в HTML-отчёт. В этой сборке нет
   визуализации, `DRAWEXE` запущен с `-b`, и открывать окна на спящей машине
   запрещено, поэтому `xwd` падает с `cannot create WIC File Stream` и роняет
   **каждый** иначе проходящий случай в `FAILED`. Снимок не несёт геометрии.
   Подмена внесена через приватный `DRAWHOME` (`tests-fillet/make_drawhome.sh`),
   потому что `testgrid` запускает **каждый случай отдельным процессом**
   `DRAWEXE` (`exec <<{} DRAWEXE -f ...` в `TestCommands.tcl`) — переопределение
   в родителе до случаев не доходит.
   До подмены сток давал 183 `FAILED`, после — 181 `OK` и 2 `BAD`.
2. **Адреса исключений нормализованы** при сравнении логов: строка
   `An exception was caught 000001FCAAD71E60 : ...` содержит адрес объекта в
   процессе и различается даже между двумя прогонами одного бинарника.

Побочная выгода от устройства `testgrid`: каждый случай и так изолирован в
своём процессе, а `tests/blend/begin` ставит `cpulimit 600`. Зависший фillet
убивается по лимиту и становится результатом, а не остановкой прогона.

## 5. Почему прежний аргумент безопасности неверен

В `DECISION.md` (раздел «Почему патч безопасен») сказано: `ChFi3d_Recale`
самозащищён — он ничего не делает, если поверхность не периодична, и даже тогда
срабатывает, только если две точки разнесены больше чем на полпериода; значит
снятие охраны `onsame` — no-op везде, кроме шва.

Ошибка в слове «значит». Вот сама функция (`ChFi3d_Builder_C1.cxx:440`):

```cpp
Handle(Geom_Surface) surf = Bs.ChangeSurface().Surface();
Handle(Geom_RectangularTrimmedSurface)
  ts = Handle(Geom_RectangularTrimmedSurface)::DownCast(surf);
if (!ts.IsNull()) surf = ts->BasisSurface();      // <-- обрезка снимается
if (surf->IsUPeriodic()) {
  Standard_Real uper = surf->UPeriod();
  if (fabs(u2-u1) > 0.5*uper) { ... сдвиг на период ... }
}
```

Две вещи вместе делают охрану бесполезной:

1. Периодичность проверяется **у базовой поверхности**, а не у грани. Тело
   вращения на 270° — это `Geom_RectangularTrimmedSurface` поверх
   `Geom_SurfaceOfRevolution`, и базовая поверхность U-периодична с периодом
   2π, хотя сама грань живёт только на 1.5π.
2. Порог — «полпериода», то есть π. На грани шириной 1.5π две **совершенно
   законные** точки могут быть разнесены больше чем на π.

В стоковом коде до этого не доходило: `onsame` был истинным только там, где
точки действительно сидят на двух берегах шва. Сняв охрану, патч начинает
«чинить» то, что не сломано: сдвигает точку на целый период и выносит её за
реальные границы грани. Окно обрезки уезжает, угол собирается не там — отсюда
незамкнутая и неориентируемая оболочка.

Иначе говоря: условие `|u2-u1| > 0.5*uper` **не эквивалентно** «точки на разных
берегах шва». Оно эквивалентно этому только для граней, покрывающих весь период.
Скругление у шва на полном цилиндре патч чинит; на теле вращения больше 180° —
ломает.

**Направление исправления** (гипотеза, не измерено): охрану нужно не снимать, а
заменить на корректную — проверять периодичность и границы **самой грани**
(`Bs.FirstUParameter()` / `LastUParameter()`), а сдвиг применять только если
результат остаётся внутри параметрических границ грани. Это надо измерять
отдельно, тем же набором.

## 6. Свой сгенерированный набор: 247 случаев, 0 отличий

Поскольку `chamfer` пропущен целиком, а в `blend` исполняется только 183 случая,
дополнительно построен систематический дифференциальный набор
(`tests-fillet/gen_seamless_group.py`, группа `seamless`). Золотых значений в нём
нет: случай печатает валидность, объём, площадь, габарит и число подформ, а
сравниваются логи двух ядер между собой.

| сетка | случаев | что покрывает |
|---|---|---|
| `prim_single` | 69 | по одному ребру куба, цилиндра, конуса, **сферы**, **тора**, радиусы 0.5/1.5/3.0 |
| `box_corner` | 34 | наборы рёбер куба, сходящиеся в вершине: 2, 3, 4 и 6 рёбер, плюс все 12 |
| `seam_rib` | 144 | радиальное ребро, приваренное к цилиндру/конусу/сфере/тору, провёрнутое вокруг оси **через полный оборот шагом 10°** (36 углов × 4 примитива), затем скругление всех рёбер |
| **итого** | **247** | |

Результат: **247 из 247 логов побайтово идентичны** между стоком и патчем
(построено 219, валидны 216 — одинаково в обоих ядрах).

Это закрывает пункт 6 раздела 9 `DECISION.md` («сферы и торы не проверялись»):
у их швов патч ничего не меняет.

Но честно: **этот набор регрессию не поймал**. Он не содержит тела вращения на
угол между 180° и 360° — а именно такая грань и ломается. Регрессию нашёл
собственный набор OCCT. Это прямой аргумент в пользу того, что самодельный
набор не заменяет штатный.

## 7. Чего этот прогон НЕ покрывает

1. **Файлы данных OCCT недоступны.** Репозиторий `occt-test-data` не
   разрешается (`git.dev.opencascade.org` не резолвится, зеркал на GitHub/GitLab
   нет). Поэтому 292 случая `blend` и **все 279** `chamfer` пропущены. Это самая
   большая дыра: пропущенные случаи — как раз сложные реальные тела.
2. **Прогнаны только `blend` и `chamfer`.** Группы `bugs` (4371 файл), `offset`,
   `feat`, `heal` не запускались.
3. **Деталь владельца на патче не проверялась** — это отдельный шаг.
4. **`checkview` подменён**, снимки не строились. На геометрию не влияет,
   но HTML-отчёт неполон.
5. **Предложенное исправление охраны (раздел 5) не реализовано и не измерено.**
6. Группа `seamless` идёт без `parse.rules`, поэтому её статусы всегда `OK`;
   сигнал в ней даёт сравнение логов, а не статус.

## 9. Вывод для проекта

Патч **перспективен, но не готов**. Починку исходного дефекта на шве этот
прогон не подтверждал и не опровергал: репро владельца в набор не входит, а
в 722 сравнённых случаях (из них реально исполнено 430: 183 в `blend` и 247 в
`seamless`) патч не дал **ни одного** улучшения — только два ухудшения. Что он чинит шов, измерено раньше (`DECISION.md`, раздел 2); что он
портит скругления на телах вращения с углом больше 180° — измерено здесь.
Ставить его в таком виде нельзя.

Следующий шаг — не «нести патч в upstream», а заменить снятую охрану на
корректную (раздел 5) и прогнать этот же набор заново; критерий приёмки —
`blend` без регрессий (181 OK) при сохранении починки репро на шве.
